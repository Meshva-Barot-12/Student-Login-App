1. System Architecture & Widget Segregation (5 Marks)

The application is built following Clean Architectural Principles separating data validation, business logic, and presentation widgets. In accordance with the assignment specifications, Stateful and Stateless widgets are strictly segregated according to mutable state requirements.

A. Widget Categorization Hierarchy

  • Stateless Widgets (Immutable Presentation): Used for interface components that do not manage mutable state across render frames. Examples include AppLogo (brand logo rendering), AuthShell (adaptive desktop/mobile layout wrapper), PasswordStrengthMeter (pure visual evaluation bar driven by score input), _FeatureBadge, and _MetricCard.
  • Stateful Widgets (Mutable Lifecycle & Interaction): Used for screens that manage dynamic user input, text controllers, focus nodes, animations, and form validation states. Examples include LoginScreen (tracks credentials, loading spinners, visibility toggles), RegistrationScreen (manages multi-field controllers and dynamic listeners), and DashboardScreen (handles session state and token view toggles).

B. Responsive Layout Engineering (AuthShell)

To ensure responsiveness across Android mobile screens, tablets, and desktop browsers, the application uses an adaptive AuthShell container built with LayoutBuilder. When screen width exceeds 920px, it displays a dual-panel split view with an institutional brand banner. On mobile screens (< 920px), it automatically transforms into an optimized single-column mobile view.

2. Form Design & Centralized Validation Suite (5 Marks)

Input validation is enforced using a centralized static Validators class. This guarantees that validation rules remain consistent across both Flutter and CLI environments.

Field Name Validation Rule & Regex Pattern Triggered Error Message
Full Name Non-empty string check after whitespace trimming 'Full Name is required'
Email Address ^[^\s@]+@[^\s@]+\.[^\s@]+$ (RFC compliant email pattern) 'Enter a valid email address'
Mobile Number ^\d{10}$ (Strict 10 numeric digits check) 'Enter a valid 10-digit mobile number'
Password Length >= 6 characters, multi-tier complexity analysis 'Password must be at least 6 characters'
Confirm Password Value exactly matches primary password string 'Passwords do not match'

Live Dynamic Password Strength Meter

The registration screen incorporates a dynamic PasswordStrengthMeter that assesses password complexity across 5 criteria: length (≥ 8), uppercase letters, lowercase letters, numeric digits, and special characters. The score smoothly animates a segmented bar transitioning from Weak (Red) → Fair (Orange) → Good (Blue) → Strong (Green).

3. Navigation Flow & Reactive State Management (5 Marks)

  • Navigator Routing: Managed seamlessly using Navigator.push (Login → Register), Navigator.pop (Register → Login), and Navigator.pushReplacement (Login → Dashboard), ensuring users cannot navigate back to the login screen after entering the portal.
  • ChangeNotifier Pattern: AuthController acts as the single source of truth for student account records, propagating state changes throughout the widget tree via notifyListeners().
  • Asynchronous Simulation: Requests simulate realistic network latency (350ms delay using Future.delayed), during which action buttons show a CircularProgressIndicator and are locked to prevent duplicate submissions.

4. Gesture Implementations & Micro-Interactions (5 Marks)

To fulfill requirement #6 ("Add at least one gesture for user interaction"), the application implements four distinct interactive gestures via GestureDetector:

  • Gesture 1 — Double-Tap on App Logo (Credential Auto-Fill): Double-tapping the logo on the Login screen triggers onDoubleTap, auto-filling the demo credentials (Meshva Barot) with animated visual feedback.
  • Gesture 2 — Long-Press on App Logo (Security Bottom Sheet): Long-pressing the logo triggers onLongPress, opening a modal bottom sheet displaying institutional security protocols.
  • Gesture 3 — Double-Tap on Student Card (Token Flip View): On the Dashboard, double-tapping the digital ID card flips it to show an encrypted session token and security verification code.
  • Gesture 4 — Long-Press on Student ID (Clipboard Copy): Long-pressing the student ID copies the ID string (STU-2026-8942) to the device clipboard with an instant confirmation badge.
